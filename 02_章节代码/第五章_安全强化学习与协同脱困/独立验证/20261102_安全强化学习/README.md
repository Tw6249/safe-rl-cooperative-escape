## 1. 对方案的核查结论

### 1.1 有证据支撑的部分

2. **硬安全与标称输入无关。** L 的每一轮提交都保持本地可行，执行段再由冻结的精确有理数证书核验；126 次 L 运行、29 500 段审计 0 失败。因此方案定理 5.1 对任意标称输入成立，包括学习得到的标称输入。它是第三章结果与执行证书的推论，不依赖强化学习。
3. **方案引用的停滞数字准确**：4 个停滞状态上单块最大改进 ≤ 9.2e-9，最小协同集跨 3 跳、8～21 个机器人；例 3.2（第三章 `ex:ch3threehop`）的停滞间隙为 0.01。
4. **残差结构、输出层零初始化与门控**是合理的工程选择：初始均值策略等于基准控制器，无冲突时保持基准行为。

### 1.2 与证据不符或缺少证据的部分

2. **七机器人反例无法用 L 训练。** 该构型（`N7_strict`）是 λ₂ 二重根（λ₃−λ₂ = 2.7e-15），`pa_bridge.build_rows` 的标量 Fiedler 行在 t=0 即抛出 `DegenerateSpectrum`。需要第四章锥行；现有 Conic NPA 实现（[06_系统验证/20261030_ConicNPA块与结清](../../../06_系统验证/20261030_ConicNPA块与结清/README.md)）使用另一套模型参数（d_safe=0.38、盒约束等），未接入第五章冻结证书。另外该场景 λ_req=2.5 远低于 λ₂（约 6.5），谱行不起作用，它是纯避碰死锁。
3. **计算量估计偏低一个数量级。** 方案称 N=7～8、B=2 单拍 < 4 ms。实测 N=8、B=2 单拍约 42 ms（不含诊断用集中 QP；含诊断约 56 ms），每拍约 26 次 CVXPY 求解，CVXPY 参数装填占大部分时间。另：本机 Windows 11 对后台进程施加 EcoQoS 降频，同一计算从 42 ms 变为约 355 ms（见 §7）。
4. **机制二（拍首边记录预调剂 Δϖ）针对的效应很小。** 第三章性质检验 B 扫描中，L 相对每拍精确 QP 的到达时间差中位数：B=8 为 +0.33 s，B=2 为 +0.75 s（6 个场景全部到达）。这是消除全部有限轮误差（包括三跳停滞）所能换回的上界。要找到跨三跳的转移方向，需要相距三跳以上节点的价格区间，一跳观测不含这一信息；而每拍 1e-4 量级的代价改进远小于任务奖励的方差，用强化学习学这一方向缺乏可行的信号。命题 5.4 第 2 条只说明沿可行下降方向走一小步会降低代价，没有说明一跳策略如何得到该方向。**本轮不训练 Δϖ。**
5. **影子价格门控与几何量高度相关。** 本地重拟合的驻点条件为 A_iᵀμ_i + W_iᵀμ_i^ws + ν_i∂‖u_i‖ = u_i^nom − u_i，即行乘子的法向组合等于滤波修正量扣除工作区与速度球的部分。μ 的大小大体可由滤波修正恢复；μ 真正额外提供的是按行归因（谱行、哪一条避碰行）。因此几何消融组必须能观测滤波修正量，否则比较会偏向代数特征。
6. **切空间闭式雅可比**忽略了经由份额分配的跨机器人耦合（NPA 中 ∂u_i/∂u_j^nom ≠ 0），在多约束同时起作用的角点（恰是死锁点）不可微、秩 2 时投影为零。PPO 把滤波当作环境的一部分，不需要它。**本轮不实现。**
7. “死锁第一主因占 95% 以上”“国际首创”“15～30 分钟收敛”没有证据支撑，本目录不采用。
8. 方案的残差项 α_rot ω J e_i、α_rad ρ e_i 在机器人到达目标后为零。七机器人反例中 7 个机器人有 5 个已在目标上，必须让出空间。L 的联合滤波可以把这些机器人推开；静态分摊下每个机器人只承担自己那一半避碰行，已到达的机器人不会让开。这正是方案命题 5.2 所说的机制，本轮用静态分摊组检验。边项 ψ_ij 在目标处不为零，是已到达机器人主动让位的唯一通道。

### 1.3 本轮范围

做：方案机制一（门控残差标称输入 + L 硬安全盾）与机制三中的停滞惩罚，用 MAPPO 训练；方案实验二中可实现的组别；实验三中的跨规模零样本迁移。
不做（如实列出）：机制二 Δϖ；切空间雅可比；MAPPO-Lagrangian 与 GCBF+ 复现；第四章锥行闭环（七机器人反例）；重根区子空间特征消融；停滞惩罚消融；多随机种子训练（每个变体只训练一次，见 §6.6 局限）。

## 2. 假设（均为待证伪）

- **H1**：学习得到的门控残差标称输入配合 L，在格点交换任务上比短视标称输入（κ=0）配合 L 到达更多。
- **H3**：动作者读取第三、四章代数量（份额、储备、本地对偶、边账本、Fiedler/子空间边特征）比只读几何量到达更多或更快。
- **H4**：相同标称规则下，静态分摊比 L 冻结更多、到达更少（方案命题 5.2 的闭环表现）。
- **H5**：N≤10 训练的策略可零样本用于 N=12、20、25，且安全不受影响。
- **S**（不是假设，是必须满足的条件）：所有组别、所有执行段审计 0 失败。

## 4. 方法（`sarl_env.ResidualFlow`、`sarl_policy`、`train_ppo`）

**标称输入**（e_i = p_i − g_i，J 为逆时针 90° 旋转）：

u_i^nom = −e_i + g_i·[2.0·ω_i·J e_i + 1.5·ρ_i·e_i + 2.0·U·mean_{j∈N_i} ψ_ij (p_i−p_j)/d_ij]，(ω, ρ, ψ) = clip(策略输出, −1, 1)。

基准项 −e_i 与组 D（κ=0）相同，不截断（由滤波执行 ‖u‖≤U）。N_i 为 2.5 m 通信图，与 L 相同。

**门控**：m_i ← max(0.97·m_i, max_{j∈N_i⁺} c_j)，g_i = tanh(4 m_i)；c_j 取上一拍的冲突信号：
- `mu`（Full 组）：‖μ_j‖，μ_j 为上一拍 L 中机器人 j 最后一次成功本地重拟合的行对偶（谱行与全部避碰行）；
- `int`（其余组）：‖u_j − Π_U(u_j^nom)‖，上一拍滤波修正量（扣除纯速度截断）。

**观测**：全部为旋转不变量（距离、内积），输出系数乘以等变向量 J e_i、e_i、(p_i−p_j)/d_ij，因而策略关于平面旋转等变。几何节点特征 12 维（距目标距离、是否到达、门控、上一拍执行速度与滤波修正在目标坐标系中的分量、谱裕度 (λ₂−λ_req)/λ_req、度、最小净空），几何边特征 13 维（距离、净空、相对位置在两端目标坐标系中的分量、邻居距目标距离、目标方向夹角、相对速度、邻居门控与修正量）。代数节点特征 5 维（谱行对偶、避碰行对偶之和、谱行份额与储备 r = U‖a_i0‖ − b_i0 − s_i0 的归一化、对偶范数），代数边特征 7 维（该对避碰行在两端的对偶、谱行与避碰行边账本、|φ₂,i−φ₂,j|、第四章子空间行差 ‖V_i−V_j‖ 与内积 ⟨V_i, V_j⟩，V=[φ₂, φ₃]）。谱信息按精确拉普拉斯矩阵给出，与 L 的假设相同。

**网络**：参数共享的消息传递网络，2 层，隐层 64，均值与最大值聚合；节点头输出 (ω, ρ)，边头输出 ψ_ij；输出层零初始化；高斯策略，状态无关对数标准差，初值 log 0.4。评论家为同结构独立网络，读全部特征并做图池化（集中训练、分布式执行）。Full 组动作者读几何 + 代数特征；Geom 与 Static 组动作者只读几何特征。

**奖励**（团队共享，每拍）：r = (D_k − D_{k+1})/D_0 − 1e-3 − 0.02·mean_i φ_i + 1[成功]，D = Σ_i‖e_i‖；φ_i = tanh(‖e_i‖/0.1)·exp(−‖u_i‖²/0.05²)·log(1+‖μ_i‖²)（方案的停滞惩罚，所有组别相同）。成功：max_i‖e_i‖ ≤ 0.01，终止。全员冻结（max_i‖u_i‖ < 0.005 连续 60 拍）终止且无奖励；滤波异常（简并谱等）或证书停止终止；500 拍截断并用价值自举。

**PPO**：γ=0.995，GAE λ=0.95，学习率 1e-3，5 轮、8 个小批次，裁剪 0.2，KL 超过 0.03 提前停止本次更新，价值系数 0.5，策略网络与价值网络分别做梯度范数裁剪 0.5（开发阶段修订，见 §8.3）；每个机器人一个比率（自身节点动作 + 出边动作），优势为团队优势；门控 ≤ 0.01 的机器人动作对环境无作用，不计入策略损失。每轮 24 个回合；预算 960 000 环境步。训练期 B=2（Static 组 B=0），使用冻结的精确证书 `certified_step`，关闭诊断用集中 QP。

## 6. 协议（运行前写定）

1. **实现核对**（`check_identity.py` → `results/check01`）：`ShieldOracle` 在冻结 `run_pa` 下必须与边账本结清 smoke01 中 L 的 2 s 运行逐位相同。
3. **正式训练**：Full、Geom、Static 三个变体各一次，超参数相同（见 `train_ppo.HP`，源码哈希写入各运行的 `protocol.json`）。训练前先对零初始化策略（均值残差为零，即目标投影标称）做一次验证，记为第 −1 轮；之后每 8 轮在验证集上做确定性评估（B 与训练相同，30 s），得分 = 成功率 − 0.001×成功回合平均用时（s），取得分最高的检查点 `best.pt` 用于测试（若第 −1 轮最高，则测试的就是初始策略，如实报告）。
5. **判读规则**：
   - S：任何组别出现审计失败即如实报告并停止对该组的性能解读。
   - H1 成立：E1 上 rl_full 到达数多于 myopic，且配对不一致对中 rl_full 占优的精确二项检验 p < 0.05。
   - H3：rl_full 与 rl_geom 按 H1 的方式比较。每个变体只有一个训练种子，差异同时包含训练随机性，结论只作初步。
   - H4：heur_st 对 heur、rl_static 对 rl_geom，比较冻结机器人拍占比与到达数。
   - H1～H4 以 E1 f=0.60 的 32 个任务判定；f=0.90 单独报告，不与 f=0.60 合并检验。样本量小，比率只解释为该场景分布上的小样本结果。
6. **局限（预先说明）**：每个变体一个训练种子；场景族只有密集三角格点交换；谱信息与通信理想同步；训练时 B=2、测试时 B=8，存在分布偏移；E2 场景此前用于其他方法。

## 7. 资源

单线程工作进程（`OMP/MKL/OPENBLAS_NUM_THREADS=1`、`torch.set_num_threads(1)`）。实际安排：Full 与 Geom 同时训练，各 8 个工作进程（另加 2 个学习器进程）；Static 在其后训练；评测 12 个工作进程，不与训练同时满载。32 个逻辑处理器中最多用约 18 个。策略更新在 RTX 4090 上进行（网络约 10 万参数，显存占用很小）。每个进程启动时调用 `sysperf.configure()`：关闭本进程的 EcoQoS 执行限速，并把优先级降为“低于正常”，保证交互程序优先；这两项设置不改变任何计算结果。区块缓存保留最近 256 个问题，避免 20261029 第三章性质检验中缓存无限增长导致的内存耗尽。

读法：
1. 全部组别审计 0 失败，最小间距 ≥ 1.000000000 m，λ₂ 下界始终不低于 λ_req。
2. **短视标称在 N=8 格点上并非全部死锁**：配合 L（B=8）有一半在 60 s 内到达，但到达很慢（中位数 39 s），冻结机器人拍占比约 0.46。方案中“短视控制 100% 陷入零速死锁”在这一场景族上不成立。
4. **静态分摊几乎全部失败**：同一环流标称下，L 到达 23 个、静态分摊 2 个（34 个配对中不一致对 21:0）。静态分摊还引起大量证书切步与 7 次证书停止：各机器人各自用满自己那一半避碰预算，零阶保持执行时越过边界，执行器只能缩短步长。这是方案命题 5.2 所述机制在闭环中的表现（开发数据，正式判定见测试）。
5. 两档谱水平几乎没有差别，促成 §3.2 的设计修订。
6. 冒烟训练（会话临时目录，不计为证据）另见一个现象：零残差策略在 4 个验证场景上 0/4，仅一次 PPO 小步更新（残差均值约 1e-3 量级）后 4/4。死锁附近的状态对微小的对称破缺很敏感，验证集成绩会有较大的偶然波动。

### 8.3 第一次正式训练尝试与超参数修订（开发阶段）

`results/train_full01`、`results/train_geom01` 按 §4 原设置（学习率 3e-4，策略与价值网络共用一个梯度范数裁剪 0.5）运行，分别在第 12 轮（12.6 万环境步）和初始验证后被中止，保留为开发证据。中止原因：前 12 轮每次更新的 KL 约 0.001～0.003，比率裁剪比例 0.002～0.011，动作标准差从 0.400 仅降到 0.382，即每轮策略只移动很小一步，按此速度在 96 万步预算内策略会停留在初始策略附近。一个可能的原因是共用的梯度裁剪让价值网络的梯度压缩了策略网络的步长。修订（两变体相同，任何测试运行之前）：学习率改为 1e-3，策略网络与价值网络分别裁剪梯度范数 0.5；其余超参数、预算与选模规则不变。修订后的运行为 `train_full02`、`train_geom02`。

此前已有的信息：初始策略（零残差）验证成功率 0.194（7/36，B=2，30 s）；Full 在第 7 轮为 0.528（19/36）。训练回合成功率在 0.29～0.67 之间波动，没有出现全员冻结终止（探索噪声使最大速度始终高于 0.005 m/s），未成功的回合都跑满 500 拍。

### 8.4 追加消融 full_int 与放弃 RL-Static（偏离预登记，任何测试运行之前决定）

**中期验证**（B=2，30 s，36 个场景；第 −1 轮为零残差初始策略）：

| 变体 | 第 −1 轮 | 第 7 轮 | 第 15 轮 |
|---|---|---|---|
| Full（几何 + 代数输入，μ 门控） | 0.194 | 0.417 | 0.500 |
| Geom（仅几何输入，修正量门控） | 0.194 | 0.472 | 0.861 |

Full 与 Geom 在**输入特征**与**门控信号**两处同时不同，若最终 Full 较差，原设计无法区分原因。一个可检验的机理是：μ 含谱行对偶，谱行由全体机器人共同承担且 ‖a_i0‖ 很小，谱裕度较紧时对偶值很大，门控对所有机器人饱和，残差处处打开。为使 H3 可解释，追加 **full_int**：动作者读取几何 + 代数特征（与 Full 相同），门控用滤波修正量（与 Geom 相同），其余与另两个变体完全相同（同一 `HP`、同一预算 96 万步、同一选模规则）。于是 full_int − Geom 只差输入特征，Full − full_int 只差门控。运行 `results/train_fullint02`，6 个工作进程（与另两个运行并行，合计 22 个工作进程，CPU 约 70%）。代码改动只把“读取代数特征的动作者”从 `variant == 'full'` 扩为 `('full', 'full_int')`，对其余变体无影响。

**放弃 RL-Static**：受计算时间限制（本机每个变体约 4～5 小时），不再训练静态分摊下的策略。命题 5.2 的机制改由“同一环流标称、只改分配方式”的 heur 与 heur_st 在测试集上检验，这一对比比两个分别训练的策略更干净；“学习能否弥补静态分摊”这一问题本轮不回答。
