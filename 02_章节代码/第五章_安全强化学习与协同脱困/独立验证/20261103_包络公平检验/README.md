# 终段包络的公平消融与新种子检验（2026-11-03，运行前登记）

本文件在运行任何作业之前写成。§1–§4 运行后不改；结果另起 §5 起追加。

## 1. 为什么要做

`20261103_终段包络验证` 给 `rl_full` 加了邻域完成包络 ρ_i = tanh(max_{j∈N_i^+}‖e_j‖/0.05)，E1/E2 共 80/80 到达。该结果有三处缺陷：

1. **事后设计。** 包络是看到 E2 的 `rl_full` 悬停之后才设计的，又在同一批 E1/E2 种子上评测，只能算开发证据。
2. **消融不公平。** 只有 `rl_full` 加了包络；`rl_geom`、`rl_full_int` 用的是不带包络的旧结果，只做过 3 s 的带包络检查。所以 “μ 门控 7:0”“代数特征 5:0” 把包络的作用记到了 μ 门控与代数特征头上。

## 2. 两组作业

- **A. 公平消融（E2，种子 20261017，已用过）**：`rl_geom_env_B8`、`rl_full_int_env_B8` 各跑 16 个场景、60 s。用途仅为 “同条件消融”，仍属样本内。

各组共用同一个运行器 `code/fair_eval.py`：同一滤波器 L（`budget_oracle`，局部结清，诊断中心 QP 关闭，诊断 QP 本来就不驱动机器人），同一审计。权重不改、不重训，ε_g=0.05 不调。每组每场景只跑一次。

## 3. 预先写下的假设与判据

到达判据沿用：最大误差 ≤ 1 cm 并保持 1 s。配对检验用不一致对的精确二项检验，双侧 α=0.05，不做单侧。

- **H-A（μ 门控 / 代数特征是否在包络之外仍有作用）**：若 `rl_geom_env` 与 `rl_full_int_env` 在 E2 上也到 16/16 或与 `rl_full_env` 无显著差异，则原文 “μ 门控唤醒邻居”“代数特征必要” 的结论不成立，只能保留 “包络消除终点悬停”。若它们仍在内部交换冻结且 `rl_full_env` 显著更多到达，则保留。
- **H-B1（学习 + L 胜过无学习标称）**：新种子上 `rl_full_env` 对 `myopic`、`heur` 的不一致对检验。
- **H-B3（包络在新种子上是否仍需要）**：`rl_full_env` 对 `rl_full`。
- **H-B4（消融在新种子上）**：`rl_full_env` 对 `rl_geom_env`、`rl_full_int_env`。

任何一组的审计失败都单独报告，不剔除。

## 4. 文件

- `code/fair_eval.py`：运行器（导入 `20261102_安全强化学习/code` 与 `20261103_终段包络验证/code/eval_env.py` 的冻结代码，不修改它们）。
- `results/run01/`：`protocol.json`（含源文件与权重 SHA256、全部作业）、`rows/`、`runs/`、`summary.json`。

## 5. 结果（运行后追加，2026-11-03）


| 组 | E2（20261017，样本内） | 新种子 20261105 |
|---|---|---|
| rl_full + 包络 | 16/16 | 16/16 |
| rl_full（无包络） | 12/16 | 13/16 |
| rl_geom + 包络 | 11/16（无包络时也是 11/16） | 11/16 |
| rl_full_int + 包络 | 9/16（无包络时也是 9/16） | 6/16 |
| 固定环流 heur | 7/16 | 6/16 |
| 短视 myopic | 4/16 | 1/16 |

按 §3 的判据：

- **H-A：保留，但只到检查点层面。** 包络对 `rl_geom`、`rl_full_int` 几乎没有作用：到达数不变，失败场景完全相同，终止误差约 1 m，是冻结而不是悬停。所以 `rl_full` 与这两个变体的差距不是包络造成的。`rl_full_env` 对 `rl_full_int_env`：E2 为 7:0（p=0.016），新种子为 10:0（p=0.0020）；对 `rl_geom_env`：两边都是 5:0（p=0.0625，不显著）。两个变体的失败全部发生在局部交换任务，置换任务都能到达。**这些数据不能确定差距来自 μ 门控本身。** 三个检查点的门控、观测特征和训练运行都不同，而且每个变体只训练了一次。带代数特征的 `rl_full_int` 反而比 `rl_geom` 更差，说明在修正量门控下代数特征没有带来好处。三者共有的区别是门控类型。若要做因果检验，可以在同一检查点上交换门控，不需要重训。
- **H-B1：成立。** `rl_full_env` 对 myopic 为 15:0（p=6.1e-5），对 heur 为 10:0（p=0.0020）。
- **H-B3：方向一致，但不显著。** `rl_full_env` 对 `rl_full` 为 3:0（p=0.25）。`rl_full` 的 3 次失败都是在 1.2–4.0 cm 处悬停。共同到达场景中，包络版的时间差中位数为 −4.0 s（9 个更快，2 个更慢）。
- **H-B4：** 见 H-A。


## 6. 视频说明更正（2026-11-03，后加）


1. **`rl_full_int + 包络` 在 H20_local1 冻结，原因不是 “门控没打开”。** 门控均值的中位数为 0.86，20 台中有 16–17 台的门控 > 0.5；门控后残差每台 RMS 的中位数为 0.206 m/s。但滤波器 L 输出的执行速度每台 RMS 中位数只有 0.004 m/s（p90 0.012），原地的 18 台在 60 s 内没有一台偏离超过 2.5 cm。也就是说，残差被 L 抵消了。
2. **`rl_geom + 包络` 在 H20_local1 不是冻结，而是活锁。** 执行速度每台 RMS 中位数 0.084 m/s，原地的 18 台中有 2–17 台偏离超过 2.5 cm，最大误差在 0.976–1.054 m 之间来回变化，互换始终没有完成。
4. **heur 在 H20_perm1 上的切步为 0。** 它在 60 s 时间上限处误差 3.64 m，此时并没有停住。
5. **myopic 在 H20_local1 于 8.45 s 按停滞规则终止**（连续 100 拍速度为零），视频此后保持最后一帧。

此外，`code/figs.py` 的矩阵图脚注原先把 “0 次审计失败” 写成固定文字（对 run01 成立），现已改为按数据计算。误差曲线里的对数下限 1e-4 m 已核对，从未触发（三条曲线的最小值为 3.4–5.1 mm）。
